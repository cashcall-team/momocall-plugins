# CRM 연동 구축

먼저 [references/output-safety.md](references/output-safety.md)의 규칙을 따른다.

## 순서
1. `momocall:get_integration_guide`로 `overview`, `data`, `crm-mapping`, `sync`, `errors`, `auth`를 읽는다.
2. `momocall:get_context`로 허용 항목을 확인한다. 개인 연결이며 회사 전체 자료는 없다.
3. 목적지 CRM의 **실제** 객체·필드·외부 ID·쓰기 권한을 확인한다(사용자가 준 문서·스키마, 또는 별도로 연결된 CRM 도구).
   임의로 짐작한 필드로 코드를 작성하지 않는다. 확인하지 못한 부분은 "가정"으로 표시한다.
4. 매핑표를 만든다. 중복 방지 키는 `call_id`다. 고객은 전화번호(`phone`, 숫자만 비교)가 같을 때만 같은 사람으로 맞춘다. 이름만으로 병합하지 않고, 번호가 없거나 여러 고객과 겹치면 사람이 확인하게 남긴다.
5. 표본 3건으로 dry-run 결과(생성·수정·미매칭·제외)를 보여 준다. `momocall:list_calls`, `momocall:get_calls` 사용.
6. 테스트 환경에 반영할 코드를 만든다.
   - 쿼리는 파라미터 바인딩과 SDK escape만 쓴다. 자격증명은 환경변수로 처리한다(값 없이 이름만 문서화).
   - 다시 실행해도 중복이 생기지 않게 upsert 방식으로 처리한다. 타임아웃이 나면 먼저 조회해서 반영되었는지 확인한 뒤 진행한다.
   - 변경분은 `get_changes`의 `sync_cursor`를 저장해 이어서 받는다. 삭제(`deleted: true`) 항목도 함께 처리한다.
   - 스크립트 인증은 `auth` 가이드대로 한다: 처음 한 번 브라우저로 로그인하고, refresh token을 환경변수·키체인에 두고 실행할 때마다 갱신해 새 값으로 바꿔 저장한다.
   - 오류는 `CODE: 설명` 형식이다. 코드별로 재시도할지(`DATA_UNAVAILABLE` 등) 멈출지(`INSUFFICIENT_SCOPE`, `CURSOR_EXPIRED` 등)를 `errors` 가이드대로 나눈다.
7. **운영 CRM 반영은 사용자가 명시적으로 승인한 뒤** 사용자가 직접 실행하도록 명령어를 안내한다.

## 하지 않는 것
- 문서만 읽고 "연동 완료"라고 말하기 (테스트 반영 결과가 있어야 함)
- 토큰·API 키를 코드에 넣기
- 전사 데이터나 녹음 파일을 기본값으로 CRM에 복사하기 (필요하면 사용자 확인을 거치고, 접근 권한이 같은지 확인해야 함)
- 대화창 안에서 수천 건을 모델로 직접 읽어 동기화하기 (스크립트가 커서로 반복 호출해야 함)

## 결과
매핑표, 실행 코드/설정, 필요한 환경변수 목록(값 없음), 초기·증분 실행 순서, dry-run·테스트 결과, 실패 목록과 재시도 방법.
