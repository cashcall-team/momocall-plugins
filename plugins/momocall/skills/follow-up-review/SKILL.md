# 놓친 약속 찾기

먼저 [references/output-safety.md](references/output-safety.md)의 규칙을 따른다.

## 순서
1. `momocall:get_context`로 허용 항목, AI 검색 남은 크레딧, 최근 동기화 시각을 확인한다.
   최근 통화가 사용자가 말한 기간보다 오래됐으면 "앱에서 아직 안 올라온 통화가 있을 수 있다"고 먼저 알린다.
2. 기간을 정한다. 별다른 말이 없으면 오늘(사용자 시간대, 기본 Asia/Seoul)로 두고 그렇게 했다고 밝힌다.
3. "전부"를 찾는 작업이므로 `momocall:list_calls`를 `next_cursor`가 없을 때까지 읽는다. AI 검색 상위 결과로 대신하지 않는다.
   통화마다 붙은 요약 한 줄(`brief`)로 약속·후속 조치가 있을 만한 통화를 추린다. 부재중이거나 요약이 없는 통화는 따로 센다.
4. 추린 통화만 `momocall:get_calls`(최대 20건씩)로 열어 전체 요약과 연결된 할 일을 읽는다.
   같은 기간의 일정·할 일은 `momocall:list_agenda`(`due_from`·`due_to`, `status: open`)로 한 번에 볼 수 있다.
5. 사용자가 **한** 약속(“제가 보내 드릴게요”)과 상대가 한 약속(“서류 보내 드릴게요”)을 구분한다.
   전사 응답에 `user_speaker`가 있을 때만 그 화자를 사용자로 본다. 없으면 누가 한 말인지 단정하지 않고 "화자 미확인"으로 적는다.
6. 후보마다 같은 상대의 이후 통화(`momocall:list_calls`에 `phone`)나 할 일 상태에서 처리 근거를 찾는다. 필요한 대목만 `momocall:get_transcript`의 `contains`로 확인한다.
7. 특정 기억만 찾으려는 추가 요청("다음 분기 연락 달라던 사람")일 때만 `momocall:search_conversations`를 1회 쓴다.

## 판정
| 상태 | 기준 |
|---|---|
| 처리됨 | 이후 통화나 완료된 할 일에 이행 근거가 있음 |
| 미처리 가능성 | 기한이 지났고 근거가 없음 |
| 기한 전 | 기한이 아직 안 됨 |
| 취소·변경 | 이후 대화에서 취소 또는 일정 변경 |
| 판단 보류 | 요약 처리 중, 잠김, 근거 부족 |

- 이후 통화가 있었다는 사실만으로 처리됨이라고 하지 않는다.
- 문자 읽기가 허용돼 있으면 `momocall:get_sms_messages`에 `phone`을 넣어 문자로 처리했는지 확인한다. 문자가 서버에 없거나 허용되지 않았으면 "문자로 보냈는지는 확인하지 못했다"고 적는다. 메일은 연결돼 있지 않다.
- 기한이 없는 약속을 오늘로 가정하지 않는다.

## 결과
고객 / 약속 내용 / 약속 시점 / 근거(call_id, 발언) / 후속 확인 / 상태 / 다음 행동 표.
마지막에 분석한 통화 수와 분석하지 못한 범위(처리 중·잠김 건수)를 적는다.
CSV를 원하면 references의 CSV 규칙을 지켜 만든다. 자동 발송은 하지 않는다.
