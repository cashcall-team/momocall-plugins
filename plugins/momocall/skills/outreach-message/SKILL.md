# 다시 연락할 사람 추리기와 문자 보내기

먼저 [references/output-safety.md](references/output-safety.md)의 규칙을 따른다.

## 순서
1. 기간을 정한다. 사용자가 말하지 않았으면 최근 30일로 하고 그렇게 했다고 알린다.
2. `momocall:list_contacts`(기간)로 그 기간에 통화한 상대를 읽는다. `next_cursor`가 있으면 끝까지 읽는다.
3. `momocall:list_calls`(같은 기간)의 요약 한 줄(`brief`)로 훑어 후보를 고른다. 사람별로 볼 때는 `phone`을 넣는다.
   - 고르는 근거는 통화에 실제로 나온 말이다: 견적·조건을 물었다, "다시 연락 달라"고 했다, 결정을 미뤘다, 약속한 답을 아직 못 줬다.
   - 요약 한 줄로 판단이 안 되는 후보만 `momocall:get_calls`로 전체 요약과 할 일을 본다. 전사는 문구를 정확히 확인해야 할 때만 본다.
   - 거절 의사를 밝혔거나 연락하지 말라고 한 사람은 뺀다. 건강·재정 같은 민감한 추정으로 고르지 않는다.
4. 문자 읽기가 허용돼 있으면 후보의 `phone`으로 `momocall:get_sms_messages`를 읽어, 이미 문자로 답했거나 최근에 문자를 주고받은 사람인지 확인한다. 문자가 서버에 없으면 그대로 진행하고, 사용자가 원할 때만 `momocall:import_sms`로 불러온다.
5. 후보 표를 보여 준다: 이름, 번호, 마지막 통화일, 마지막 문자일(읽었다면), 고른 근거 한 줄, 근거 통화(call_id). 성사 가능성은 추정이라고 밝힌다.
6. 사용자가 고른 사람마다 문자 초안을 쓴다. 사용자의 평소 말투를 모르면 짧고 정중하게 쓰고, 통화에서 확인된 사실만 넣는다. 가격·조건·약속을 새로 만들어 넣지 않는다.
7. 받는 사람 전체와 사람별 문자 내용 전체를 한 번에 보여 주고 확인받는다. 사용자가 고치면 고친 내용으로 다시 보여 준다.
8. 확인받은 뒤 사람마다 `momocall:send_sms`(phone, body)를 부른다. 확인받지 않은 사람이나 내용은 보내지 않는다.
9. `momocall:get_sms_status`로 결과를 확인해 보냄·실패를 사람별로 알린다. 실패한 건은 사유를 알리고, 다시 보낼지 사용자에게 묻는다.

## 결과
- 보낸 사람·번호·보낸 내용·결과(sent·failed) 표.
- 보내지 않은 후보와 이유.
- 문자 연결이 꺼져 있거나(`SMS_PHONE_NOT_LINKED`) 휴대폰이 등록되지 않았으면(`SMS_NO_DEVICE`) 초안만 정리해 주고, 켜는 방법을 안내한다.
